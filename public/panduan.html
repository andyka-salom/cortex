Panduan Pemakaian

Langkah demi langkah memakai Cortex — dari menambah VPS pertama sampai memantau alert. Sesuaikan langkah dengan role akun Anda.

Alur Utama 1. Tambah VPS 2. Web Terminal 3. File Transfer 4. Dashboard & Alert 5. Threshold & Sync Prometheus 6. User & Role 7. Audit Log 8. AI Chat Hak Akses per Role

Alur Utama (Happy Path)

Superadmin tambah VPS baru (IP + SSH key VPS yang masih bersih) → sistem otomatis menjalankan provisioning (install Docker → setup user → deploy Node Exporter + cAdvisor → setup firewall → daftar ke Prometheus) → status VPS berubah ACTIVE → VPS langsung muncul di Dashboard & Grafana → semua user berwenang bisa akses terminal / upload file kapan saja → alert otomatis jalan begitu metric terpantau.

1

Tambah VPS & Provisioning Otomatis

Role: Superadmin. Buka Dashboard → tombol Tambah VPS.

  • Isi Nama VPS (unik), IP Address, SSH Port (default 22), SSH User.
  • Pilih Environment (Production/Staging) dan Group (mis. ERP, POS, Ecommerce) — dipakai untuk filter di Grafana.
  • Tempel SSH Private Key milik VPS target (masih fresh install Ubuntu, akses root/sudo NOPASSWD). Key langsung dienkripsi AES-256-GCM sebelum disimpan — tidak pernah ditampilkan lagi setelah tersimpan.
  • Klik Simpan & Provision — job provisioning berjalan di background (BullMQ), status VPS berubah PROVISIONING lalu ACTIVE kalau berhasil.
  • Klik nama VPS di tabel untuk lihat detail log provisioning step-by-step. Kalau gagal (status ERROR), baca log lalu klik Re-provision — semua step idempotent, aman diulang tanpa efek samping.
  • Untuk banyak VPS sekaligus, pakai Bulk Import (paste JSON array VPS).
2

Akses Web Terminal (SSH via Browser)

Role: Superadmin & Operator. Buka Terminal di sidebar, atau tombol Terminal di baris VPS pada Dashboard.

  • Pilih VPS yang statusnya ACTIVE — terminal langsung connect via SSH memakai key yang tersimpan (didekripsi hanya di memory server, tidak pernah dikirim ke browser).
  • Setiap session tercatat sebagai TERMINAL_SESSION_START/END di Audit Log, lengkap dengan command yang diketik (best-effort, untuk keperluan audit).
  • Bisa buka beberapa tab/VPS sekaligus — tiap tab = 1 session terpisah.
  • Viewer tidak bisa membuka terminal sama sekali (ditolak di server, bukan cuma disembunyikan di UI).
3

File Transfer (Upload/Download via SFTP)

Role: Superadmin & Operator. Buka File Transfer → pilih VPS → Hubungkan SFTP.

  • Jelajahi direktori VPS, upload file (drag & drop atau pilih file), atau download file yang ada.
  • Path tujuan dibatasi whitelist server (default /tmp, /home, /var/www, /opt — bisa diubah lewat env FILE_TRANSFER_ALLOWED_PATHS). Path di luar whitelist akan ditolak.
  • Semua transfer (siapa, kapan, file apa, ke VPS mana) tercatat otomatis dan bisa dilihat riwayatnya.
4

Pantau Dashboard & Alert

Role: semua (Superadmin, Operator, Viewer).

  • Dashboard — ringkasan jumlah VPS, status Active/Error, dan alert aktif. Filter berdasarkan Environment atau Group. Auto-refresh tiap 10 detik.
  • Alerts — daftar alert firing/silenced dari Alertmanager. Perlu set ALERTMANAGER_URL di .env dulu supaya terhubung; kalau kosong, halaman akan menampilkan pesan "belum terkonfigurasi" (bukan error).
  • Superadmin/Operator bisa acknowledge/silence alert langsung dari halaman ini.
  • Untuk detail metric per VPS (grafik historis CPU/RAM/Disk), buka Grafana terpisah — Cortex hanya menampilkan ringkasan.
5

Atur Threshold Alert & Sync Target Prometheus

Role: Superadmin. Buka Settings.

  • Alert Thresholds — set batas CPU/RAM/Disk (%) dan durasi (menit) sebelum alert firing. Scope bisa Global (semua VPS) atau VPS tertentu. Klik Simpan untuk upsert — otomatis meng-generate ulang file Prometheus rules.
  • Prometheus Targets Sync — kalau ada VPS ACTIVE yang belum muncul di Prometheus (mis. file target sempat terhapus manual), klik Re-sync Target Sekarang untuk regenerasi semua file file_sd dari database.
  • Target Prometheus tidak pernah ditulis lewat edit prometheus.yml manual — semua lewat file JSON di direktori PROMETHEUS_TARGETS_DIR yang otomatis di-reload Prometheus.
6

Kelola User & Role

Role: Superadmin. Buka Users → Tambah User.

  • Set nama, email, password awal, dan role (Superadmin/Operator/Viewer) — lihat tabel hak akses di bawah.
  • Nonaktifkan (bukan hapus) user yang keluar/resign — histori audit log tetap tersimpan.
  • Reset password user lain kapan saja lewat tombol Reset Password di baris user.
7

Audit Log

Role: Superadmin. Buka Audit Log.

  • Semua aksi sensitif tercatat: provisioning, command terminal per session, file transfer, perubahan konfigurasi VPS, login/logout — append-only, tidak bisa diedit/dihapus lewat aplikasi.
  • Filter berdasarkan User ID, VPS ID, jenis aksi, atau rentang tanggal.
  • Klik Export CSV untuk keperluan audit internal atau kepatuhan.
8

AI Chat (mode caveman)

Role: Superadmin saja. Buka AI Chat.

  • AI menjawab dengan gaya singkat & blak-blakan ("mode caveman") — tetap akurat secara teknis, cuma tidak bertele-tele.
  • AI bisa bantu diagnosis (mis. "cek disk usage VPS X") dan boleh mengusulkan command shell untuk dijalankan — tapi command TIDAK PERNAH langsung dieksekusi. Selalu tampil sebagai kartu konfirmasi berisi nama VPS, alasan, dan command persis, dengan tombol Jalankan / Tolak.
  • AI hanya boleh menyentuh VPS yang di-toggle AI Access (kolom di tabel Dashboard) — default OFF untuk semua VPS. Nyalakan hanya untuk VPS yang memang ingin dibantu AI (mis. staging), matikan untuk VPS sensitif.
  • Setiap command yang benar-benar dijalankan (atau ditolak) tercatat di Audit Log, lengkap dengan alasan yang diajukan AI dan hasil eksekusinya.
  • Riwayat chat tersimpan sementara di memory server (hilang kalau server restart) — klik Chat Baru untuk mulai sesi baru kapan saja.
